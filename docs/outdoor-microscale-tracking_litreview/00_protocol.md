# 문헌조사 프로토콜: 실외 환경 마이크로스케일 위치 트래킹

- **작성일**: 2026-08-01
- **맥락**: 국립중앙과학관 야외 GNSS 레이더 내비게이션 프로젝트(GNSSnavi).
  현재 스마트폰 브라우저 GNSS로 ±8~11m 를 얻고 있으나, 20m 간격의 인접 전시관 구분과
  반경 28m 지오펜스 진입 판정에서 한계에 부딪혔다. 자체 해법을 더 만들기 전에
  **이 문제를 남들은 어떻게 풀었는지** 먼저 확인한다.

## 연구질문

**주질문**
> 실외 문화시설 부지에서 방문객 위치를 미터 단위로 추정하기 위해 어떤 기술·방법이 연구·구현되어
> 왔으며, 각각이 실제로 달성한 정확도와 그 전제조건(인프라·기기·비용)은 무엇인가?

**하위질문** (범위: **추가 인프라를 설치하지 않는 방법**으로 한정 — 사용자 결정 2026-08-01)
1. **추가 인프라 없이 스마트폰만으로** 달성 가능한 실외 측위 정확도의 실질적 한계는 얼마인가?
2. **맵매칭**(보도·경로 스냅)은 실측에서 얼마나 개선하며, 적용 전제(경로망 데이터)는 무엇인가?
3. **센서융합·추측항법**은 스마트폰에서 실제로 얼마나 이득이 있는가? (특히 단시간·단거리)
4. **지오펜싱(구역 진입 판정)** 의 실제 신뢰도는 얼마이며, 반경·체류시간 설계 지침이 존재하는가?
5. 박물관·과학관·공원 등 **야외 부지에 실제 적용된 구현사례**와 그 교훈은 무엇인가?

## PCC

- **Population**: 야외를 이동하는 방문객·보행자 (스마트폰 소지, 일반 소비자 기기)
- **Concept**: 마이크로스케일(미터 단위) 위치 추정 — GNSS 보강, 대체 측위, 센서 융합,
  맵매칭, 지오펜싱 신뢰도
- **Context**: 과학관·박물관·공원·캠퍼스 등 문화·공공시설 **야외 부지**
  (개활지부터 반차폐 구조물 아래까지), 웹/모바일 안내 서비스

## 포함 기준

- 실외 또는 **실내외 연속(seamless)** 환경의 보행자·방문객 위치추정을 다룬 학술문헌
- **달성 정확도를 수치로 보고**한 것 (m 단위, CEP/RMSE/백분위 등)
- 지오펜싱·근접 판정의 신뢰도나 설계 기준을 다룬 것
- 문화·공공시설 야외 안내 **구현사례** (사용자가 명시 요청 → 회색문헌 의도적 포함,
  단 매트릭스에서 `문헌유형` 으로 구분 표기)
- 시간 범위: **2013–현재** (스마트폰 이중주파수·RTK 대중화 이후가 핵심.
  단 지오펜싱·관람객 동선 연구의 정전은 이전 것도 허용)
- 언어: 국문·영문

## 배제 기준

- **차량 전용** 측위 (보행자 적용 논의가 없는 것)
- **부지에 인프라 설치를 전제하는 방법** (UWB 앵커, BLE 비콘 망, 자체 RTK 기준국 등)
  — 사용자 결정으로 범위에서 제외. 단 **정확도 비교 기준(benchmark)으로 언급되는 수치는 인용 허용**
  (예: "UWB 는 dm 급인데 우리는 m 급" 같은 대조). 공개 인프라를 무상 이용하는 경우
  (예: 국가 SBAS/KASS, 통신사 RTK 망 등 설치 불요)는 경계 사례로 두고 발견 시 별도 표기
- **순수 실내 전용** 측위 (실외 연계 논의 없음)
- 정확도 수치 없이 개념·구상만 제시한 것
- 기술적 근거 없는 상용 제품 홍보물
- 초록만 있고 판단 근거가 부족한 것

**경계 사례 사전 결정**: 순수 실내 측위는 원칙 배제하되 "실내외 연속" 연구는 포함.
도심 협곡(urban canyon) 연구는 반차폐 조건이 우리 아치 터널과 유사하므로 **포함**.

## 대상 DB 및 실행 경로

이 환경은 샌드박스로 **직접 API 호출이 프록시에 차단**(OpenAlex·Crossref·Semantic Scholar 모두 403)되고
WebFetch 도 해당 API 에 대해 403 이다. 확인된 가용 경로는 **WebSearch** 뿐이다.

- **국제**: OpenAlex·Semantic Scholar·arXiv·MDPI(Sensors)·IEEE·Springer — WebSearch 로 접근
- **국내**: RISS·KCI·DBpia — WebSearch 로 접근 (API 없음)
- 검색 질의문·날짜·건수는 `01_search_log.md` 에 기록

## 한계 (미리 명시)

- WebSearch 경유라 DB별 정밀 질의문(불리언·필드 제한)을 완전히 통제하지 못한다.
  따라서 PRISMA 숫자는 "검색 엔진이 반환한 후보" 기준이며, DB 전수 검색과 동일하지 않다.
- 유료 논문은 초록까지만 판단 가능한 경우가 있다. 그 경우 매트릭스에 `초록기반` 으로 표기한다.
