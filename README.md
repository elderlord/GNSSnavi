# 국립중앙과학관 야외 GNSS 레이더 내비게이션

야외 부지에서 관람객이 전시관의 **방향·직선거리**를 드래곤볼 레이더 형태로 확인하는 웹앱.
단일 파일·오프라인·모바일(iPad/스마트폰) 대응. 서버 없음, 전부 클라이언트 사이드.

> ⚠️ HTTPS 필수 — Geolocation / DeviceOrientation API는 보안 컨텍스트에서만 동작합니다.
> GitHub Pages 배포 권장.

## 파일

| 파일 | 용도 |
|---|---|
| `index.html` | 레이더 내비게이션 본체 (자체 완결, 오프라인) |
| `collect.html` | 현장 좌표 수집 도구 (30초 수집 → 중앙값 산출·복사, **품질 게이트 ±12m**) |
| `diag.html` | GPS 진단 도구 (60초간 원시 샘플 전부 기록 — 락 실패·군집 분리 확인용) |
| `path.html` | 산책로 기록 도구 (걸으며 트랙 기록 → 단순화 → `PATHS` 스니펫) |
| `docs/field-2026-08-03.md` | **현장 측량 기록** — 관 좌표·경로망·출입구를 한 곳에. `plan.html` 에 그대로 붙여넣어 복원 가능 |
| `plan.html` | 경로망 편집기 (실측 관·걸은 궤적 위에 경로를 그려 `PATHS` 생성, 실제 문 위치 기록) |
| `maps/` | 건물별 실내 약도 이미지 (`hall-01.png` …) — ★ 아직 없음 |

## 현재 상태 (v1)

인수인계서(§6)의 구현 단계를 기준으로:

- [x] 1. 좌표 수집 페이지 `collect.html` — 30초 수집·중앙값·복사
- [x] 2. 레이더 렌더링 — Haversine 거리/방위, 2단 고정 스케일(0~150m→0~60%, 150~600m→60~100%)
- [x] 3. 실시간 위치 연동 — `watchPosition` + 지수이동평균 보간(정확도 나쁠수록 천천히)
- [x] 4. 방향 정렬 4방식 — North-up 기본 / 나침반 / **GPS 진행방향** / **손가락 수동 회전**
- [x] 5. 지오펜스 + 댐퍼 → 약도 전환 — 원형 판정, `R_out = radiusIn + 15m`, `T = 3초`,
      **정확도 적응**(위치가 부정확하면 자동 전환 대신 수동 약도 버튼)
- [x] 6. 드래곤볼 레이더 스타일 — 동심원 링·방위 눈금·회전 스캔라인·점멸 마커
- [x] 실내 진입 약도 — 관별 층 약도 이미지 연결 (없는 관은 자체 도식으로 폴백)
- [x] 실내 약도 층 구분 — 관별 **층 선택 탭**(수동). 실내는 측위가 없어 자동 층감지 불가
- [x] 배경 약도 — 부지 도식을 레이더 좌표계에 정렬해 반투명 렌더 + 현재 좌표 표시(탭 복사)
- [x] **7개 관 좌표 현장 실측 완료** (2026-08-03) — 전부 위성락 ±6~10m, 게이트 통과
- [x] 산책로 경로망 스냅 — 위치를 등록된 경로 위로 끌어와 횡방향 오차 감소

> **경로망 스냅 (`PATHS`)**
> 관람객이 실제로 다니는 산책로를 폴리라인으로 등록하면, 위치가 경로 위로 보정되어
> **횡방향 오차가 산책로 폭으로 제한**됩니다. 관 입구로 이어지는 **지선(spur)** 에
> `venue` 를 달아두면, 어느 지선에 스냅되는지가 곧 어느 관인지가 되어
> **20m 간격으로 붙어 있는 인접 관도 구분**됩니다.
>
> - 기록: `path.html` 로 산책로를 걸으며 기록 → 스니펫을 `index.html` 의 `PATHS` 에 붙여넣기
> - 검증: 앱의 `🛤 경로스냅` 토글로 스냅 전/후를 눈으로 비교
> - 파라미터: `SNAP.PATH_ERR`(경로망 자체 오차) `K_TOL`(허용 배수) `SNAP_MAX`(절대 상한) `MAX_W`(최대 스냅 강도)
> - `PATHS` 가 비어 있으면 스냅은 비활성이고 기존 동작이 그대로 유지됩니다
> - **주의**: 스냅은 표시·판정에만 쓰고 좌표 수집(`collect.html`)과 화면의 좌표 readout 에는
>   적용하지 않습니다. 측정값에 보정을 섞으면 실측의 의미가 사라집니다
> - 근거·한계: `docs/outdoor-microscale-tracking_litreview/08_implications.md`
>   (문헌 성능은 도시 교통망 기준이고 과학관 산책로 규모의 선행연구는 없습니다 — 현장 검증 필수)
> - 검증 테스트: `node test/path-record.test.js` (기록 도구) · `node test/plan-editor.test.js` (편집기)
>   · `node test/path-snap.test.js` (스냅 엔진)
>
> **`plan.html` — GPS 가 담지 못하는 것을 사람이 넣는 곳**
> GPS 트랙은 "폰이 어디라고 생각했는가"만 담습니다. 길이 어떻게 갈라지는지, 문이 정확히
> 어디인지는 현장을 아는 사람만 압니다. 실측 관 7개와 걸은 궤적을 배경에 깔고 그 위에
> 경로를 그리면, **실측과 같은 기준계**로 `PATHS` 가 나옵니다.
> 배경 이미지는 기기에서만 불러오며 저장소에 들어가지 않습니다.
> 손으로 찍은 **실제 문 위치는 `VENUES` 를 덮어쓰지 않고** 별도로 기록되며,
> 실측 좌표와의 거리·방위를 보여줍니다.

**연결된 층 약도** (`maps/`, 7개 관 전부): 자연사관(1·2층) · 과학기술관(지하1·1·중층·2층) ·
미래기술관(1·2층) · 창의나래관(1·2·3층) · 어린이과학관(1·2층) · 천체관(단일) · 생물탐구관(단일).

**배경 약도로 실측 좌표 확인**: `🗺 배경약도` 버튼을 켜면 부지 건물 블록이 레이더 위에
겹쳐 그려지고, 화면 좌상단에 현재 GPS 좌표가 뜹니다(탭하면 복사). 실제 건물 앞에 서서
그 건물 블록이 레이더 중심(현재 위치)에 오는지 보며 `VENUES` 좌표의 정확도를 확인/조정합니다.
※ 레이더 반경이 2단(비선형)이라 배경은 **내부 150m 선형존**에서 정확히 정렬됩니다(외곽은 압축존과 어긋남).

**방향 정렬 (나침반이 부정확할 때)**: 나침반은 철제 구조물·전시물 근처에서 자주 틀어지므로,
의존하지 않는 대안을 제공합니다. 컨트롤 바에서 선택:
- **North-up**(기본): 화면 위 = 북쪽 고정
- **🧭 나침반**: 기기 방위 사용(iOS는 권한 요청). 값이 끊기거나 튀면 자동 North-up 폴백
- **🚶 진행방향**: 걸을 때 GPS 위치 변화로 진행방향을 계산해 '내가 향한 쪽'을 화면 위로. 나침반 불필요, 정지 시 마지막 방향 유지
- **손가락 회전**: 레이더를 드래그해 실제 방향과 수동으로 맞춤(마커·배경·방위가 함께 회전)
- **◎ 정렬 리셋**: North-up 복귀 + 수동각 초기화 + 위치 튐 리셋

**전시관 7개 확정**: 자연사관 · 과학기술관 · 미래기술관 · 창의나래관 · 어린이과학관 · 생물탐구관 · **천체관**.
공식 안내도의 상대 배치를 참조해 배치했습니다. (천체관 = N3, 벽면 대형 달 인쇄)

**실내 약도**: 관별 상세 약도 이미지가 아직 없어, 진입 시 **자체 제작 부지 도식**에서
해당 관을 하이라이트해 보여줍니다(안내도를 픽셀로 재현 — §9-4 허용).
표시 우선순위: `floors[]`(층별) → `mapImage`(단일) → 자체 도식.

**층 구분(중요)**: 실내에는 GPS·WiFi 측위가 없어 **층을 자동으로 알 수 없습니다.**
그래서 관람객이 직접 고르는 **층 선택 탭** 방식을 씁니다. `VENUES` 항목에 층 배열을 넣으면
약도 상단에 탭이 뜨고, 탭을 누르면 해당 층 약도로 전환됩니다.

```js
{ id:"hall-tech", name:"과학기술관", lat:..., lng:..., radiusIn:30,
  floors:[
    { label:"지하1층", img:"maps/hall-tech-b1f.png" },
    { label:"1층", main:true, img:"maps/hall-tech-1f.png" }, // main:true = 진입 시 기본 표시 층
    { label:"중층", img:"maps/hall-tech-1mf.png" },
    { label:"2층", img:"maps/hall-tech-2f.png" },
  ] }
```
- `main:true`인 층이 진입 시 기본으로 뜹니다(보통 입구층). 없으면 첫 층.
- 층이 하나뿐이면 `mapImage`(단일)만 지정 → 탭 없이 바로 표시(예: 천체관).
- 이미지가 없으면 그 층 자리에 "약도 준비 중"이 뜹니다(탭은 정상 동작).

**시뮬레이션 모드**: GPS 없이도 `▶︎ 시뮬레이션` 버튼 → 화면 드래그로 부지를 걸어다니며
마커 배치·지오펜스 전환을 검증할 수 있습니다.

## ★ 착수 전 필요한 실데이터

`index.html` 상단 `VENUES` / `SITE_CENTER` 좌표는 **국립중앙과학관 부근의 임시 더미값**입니다.
현장에서 다음을 채워야 실사용 가능합니다.

> **좌표 채택 기준: 정확도 ±12m 이하 (위성 락)**
> 이 기준을 넘으면 `collect.html`이 좌표를 아예 내주지 않습니다(복사 버튼 비활성).
> 근거: 관 좌표 오차 + 실시간 위치 오차(±12m)의 합성이 진입 반경 28m를 해상해야 합니다.
> ±12m까지는 「정문 앞 진입 ≥95%, 45m 밖 오진입 ≤5%」를 만족하지만, ±21m면 정문 앞 진입
> 성공률이 82%까지 떨어집니다. 네트워크(WiFi/셀) 측위는 보통 ±20m대라 이 기준에 걸립니다.
> 검증 테스트: `node test/collect-gate.test.js`

> **진입 판정은 실시간 정확도에 적응합니다**
> 위치 오차가 커지면 진입 반경을 좁히고(오진입 방지) 이탈 반경을 넓힙니다(오이탈 방지).
> 유효 진입반경이 8m 미만이 될 만큼(대략 `accuracy` ±40m 초과) 부정확하면 **자동 전환을
> 포기**하고, 근처일 때 「🏛 OO 약도 보기」 버튼만 띄워 관람객이 직접 열도록 합니다.
> 파라미터: `GEO.ACC_K` / `GEO.MIN_EFF_R` / `GEO.NEAR_MULT`.
> 검증 테스트: `node test/geofence-adaptive.test.js`

1. **좌표 실측** — 각 건물 정문에서 `collect.html`로 30초 수집한 **중앙값**을 `VENUES`에 반영
   (지도에서 눈대중으로 따면 건물 중심이 잡혀 정문과 20~30m 어긋남).
   현재 6개 관 좌표는 안내도 배치를 참조한 더미이므로 반드시 실측값으로 교체
2. ~~전시관 목록 확정~~ → **확정됨(6개)**. 향후 추가 시 `VENUES`에 항목만 더하면 됨(상한 8~12개)
3. **관별 상세 약도(선택)** — `maps/hall-XX.png` 배치 후 `mapImage` 지정 시 자체 도식 대신 사용
4. **배경 약도(선택)** — `SITE_MAP`에 이미지 + 대각 기준점 2개(실좌표+픽셀좌표) 기록

## 알려진 한계 (인수인계서 §8)

- 실외 GPS 오차 10~15m. 방향 안내엔 무해하나 "바로 앞 몇 m"는 불가
- 건물 진입/이탈 감지 최대 3초 지연(댐퍼)
- 나침반 미지원 기기는 North-up 고정(화면 위 = 북쪽)
- 건물 사이 좁은 통로는 멀티패스로 위치가 튈 수 있음
- **배경 약도 정렬**: 레이더 반경이 2단(비선형)이라 평면 약도는 전체를 정렬할 수 없음.
  v1은 내부 150m 선형존에만 맞추는 방식으로 설계했고, 실좌표 확보 시 구현 확장 예정

## 미결 사항 (인수인계서 §9)

1. **약도** — ✅ 현 버전은 자체 부지 도식으로 처리. 관별 상세도가 필요하면 `maps/`에 추가
2. **전시관 목록** — ✅ 7개 확정 (자연사관·과학기술관·미래기술관·창의나래관·어린이과학관·생물탐구관·천체관)
3. **QR 웨이포인트 앱** — 🔜 **향후 통합 예정**(현재 별개 모듈). 통합 시 QR `zone` 파라미터로
   지오펜스를 보완하는 방식 검토
4. **오프라인 범위** — 상세 약도/배경 이미지까지 번들할지 (현재 도식은 SVG라 번들 불필요)

## 로컬 실행

Geolocation은 `file://`에서 제한되므로 로컬 HTTPS/localhost로 띄웁니다.

```bash
python3 -m http.server 8000
# http://localhost:8000/index.html  (모바일 실측은 HTTPS 배포에서)
```
